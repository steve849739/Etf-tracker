# 外部定时触发配置指南（备用方案）

> 用途：解决 GitHub Actions `schedule` 定时任务不触发/延迟的问题（本仓库已实锤 4 次：8-3/8-5/8-6 未触发、8-4 延迟 3 小时 19 分）。
> 原理：用第三方定时服务 cron-job.org 每天准时调用 GitHub API 触发 `workflow_dispatch`（手动触发路径 100% 稳定）。
> 配置完成后可长期免手动。schedule 保留作双保险（脚本幂等，双触发不会重复写数据）。

## 流程

```
每天 09:00(北京)
   │  cron-job.org 定时触发
   ▼
POST https://api.github.com/repos/steve849739/Etf-tracker/actions/workflows/update-pages.yml/dispatches
   │  (带 PAT 认证, body: {"ref":"main"})
   ▼
GitHub 立即执行 workflow（等价于手动点 Run）→ 抓数据 → 生成页面 → 部署
```

## 第 1 步：创建 GitHub Token（约 5 分钟）

1. 打开 https://github.com/settings/tokens?type=beta （或 GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens）
2. 点 **Generate new token**
3. 填 Token name（如 `cron-trigger`），Expiration 选 90 天或自定义
4. **Repository access**：选 **Only select repositories** → 勾选 `Etf-tracker`
5. **Permissions** → Repository permissions → **Actions** 选 **Read and write**（只需这一个权限）
6. 点 Generate token，**立即复制**（只显示一次，关掉就看不到了）

> ⚠️ Token 就是"钥匙"，只给 cron-job.org 用。泄露时去同一页面点 Revoke 即可作废，不影响其他东西。

## 第 2 步：注册 cron-job.org（约 5 分钟）

1. 打开 https://cron-job.org ，注册账号（免费）
2. 登录后点 **Create cronjob**
3. 按下面配置：

| 字段 | 值 |
|---|---|
| **URL** | `https://api.github.com/repos/steve849739/Etf-tracker/actions/workflows/update-pages.yml/dispatches` |
| **Request method** | `POST` |
| **Payload / Body** | `{"ref":"main"}` |
| **Headers**（新增 2 个） | `Authorization: Bearer <第1步的Token>`<br>`Accept: application/vnd.github+json`<br>`X-GitHub-Api-Version: 2022-11-28` |
| **Schedule** | 每天 `09:00`（时区选 **Asia/Shanghai** 北京时间；交易所 7 点更新前一日数据，9 点抓取留 2 小时缓冲） |

4. 保存前先点 **Run once now**（或保存后手动执行一次）——若 GitHub Actions 立刻出现新 run，说明配置成功
5. 保存并启用（Enable）

> cron-job.org 免费版请求间隔约 1 分钟一次，每天一次完全够用，无需付费。

## 第 3 步：验证

1. 等 cron-job.org 定时任务到点执行，或手动 Run once now
2. 打开 https://github.com/steve849739/Etf-tracker/actions 看是否有 `workflow_dispatch` 事件的新 run
3. 确认页面 https://steve849739.github.io/Etf-tracker/ 数据更新

## 双保险说明

- 保留 workflow 里的 `schedule`（北京 9:30）不动：万一它也触发，两个 run 同时跑，`etf_update.py` 的同日期幂等逻辑会跳过重复写入，不会产生脏数据
- 外部触发为主（9:00 先跑），schedule 为兜底（9:30 后跑）——即使 schedule 永远不触发，数据也每天都有

## 常见问题

- **403 错误**：Token 权限不足或已过期 → 检查 Actions 权限是否 Read and write、Token 是否未过期
- **404 错误**：仓库名或 workflow 文件名不对 → 确认 URL 里是 `Etf-tracker` 和 `update-pages.yml`
- **Token 过期**：Fine-grained token 有有效期，到期前 1 个月回 cron-job.org 更新 Headers 里的 Token
